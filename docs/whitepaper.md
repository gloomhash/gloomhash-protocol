# GLOOMHASH Whitepaper

## Vision and mission

Market screens are loud. They ask for wallets, signatures and attention, then
sell all three. GLOOMHASH takes the opposite stance: one quiet terminal that
reads public Solana data and asks for nothing in return.

**Mission:** keep an honest, read-only view of where paid attention is flowing
on Solana, and give holders one registry they can check any address against.

**Principles**

1. Read, never request. No wallet connection, no signatures, no keys.
2. One record per fact. Contract, links and sources each carry a state:
   stated, absent or unconfirmed. Anything not stated is inert.
3. Stale beats blank. Failed refreshes keep the last good figures visible.
4. Inspectable. The registry, gates and market code are plain modules.

## Roadmap

**Phase 1: Signal.** Ship the market board, ticker and address checker.
Publish the source. State the contract address in the registry.

**Phase 2: Depth.** Add per-token detail panels, richer pair selection and a
longer view of volume and liquidity movement. Keep every source public.

**Phase 3: Guard.** Extend the registry gate with community-submitted
look-alike reports and a shareable verdict link for any address.

**Phase 4: Open.** Stabilise the module interfaces so others can fork the
board for different chains while keeping the register pattern intact.
